### `POST /customer/link` — Link an identifier combination to your external_id

- **operationId:** `customers.link`

- **Auth:** Bearer API key, scope `customers:write`
- **Pagination:** None documented — single response.
- **SDK auto-retry:** yes (documented idempotent)
- **Statuses:** 201 Success, 401 Error, 403 Error, 404 Error

> Register a business identity link: map an identifier combination (email/mobile[+name]) to YOUR external_id. Combinations are AND — {email, name} separates family members sharing an email. APPLIED NOW: an existing customer consistent with EVERY identifier you send (sharing one of them is not enough) gets the external_id immediately (`applied_customer_id` in the response); otherwise it applies at that person's first contact, on every channel. Customers are NEVER merged: identifiers that match two existing customers, or a customer already linked to another id, are refused with 409 `identity_conflict`. Linking identifiers that an existing link to a DIFFERENT external_id would also match is refused with 409 `link_conflict` — DELETE the old link first. Re-sending the identical link is idempotent.

Audio takes no caption (Meta has no field for it) and `filename` applies to documents only — both are refused rather than silently dropped. 🛑 An owning agent with no WhatsApp Sender action on its canvas is refused with 422 `sender_not_authorized` BEFORE anything is written, so nothing is ever recorded as sent when nothing went out. - **operationId:** `templates.list`

Outside WhatsApp's 24-hour service window a template is the only thing deliverable, and `POST /api/v1/messages` takes one by `name` — this is how you discover which names exist and what they need. Only `status: "approved"` is sendable. Served from the copy this workspace holds, so it never touches a provider and never inherits their rate limits — `synced_at` says when that copy was last refreshed by `POST /api/v1/templates/sync`. 🛑 `synced_at: null` means this workspace has NEVER synced, which is a different statement from "you have no approved templates": an empty list WITH a timestamp means the providers genuinely reported none. Approval is asynchronous and the provider owns `status`, so a stored verdict can lag — sync before acting on one if it matters. ### `PATCH /webhook-subscriptions/{id}` — Update or re-enable a subscription

- **operationId:** `webhooks.patch`
- **SDK method:** `webhooks.update`
- **Auth:** Bearer API key, scope `webhooks:write`
- **Pagination:** None documented — single response.
- **SDK auto-retry:** no (opt-in) — rotate_secret would mint a second secret
